# Coding Rules

## Package Management

- Install modules: `pnpm add <package>`
- Uninstall modules: `pnpm remove <package>`

## TypeScript Configuration

- **DO NOT modify** `tsconfig.json` `paths` settings
- If path changes are needed, use `AskUserQuestion` to discuss first

## Development Scripts

Monorepo (pnpm workspaces: `packages/core`, `packages/cli`, later `apps/mcp`). Root scripts run recursively (`pnpm -r run …`).

| Command          | Description                                                                 |
| ---------------- | --------------------------------------------------------------------------- |
| `pnpm build`     | `tsdown` in every package (rewrites each package.json `exports` / `publishConfig`) |
| `pnpm lint`      | `oxfmt --check . && oxlint .` in every package                              |
| `pnpm fmt`       | `oxfmt --write . && oxlint --fix .` in every package                        |
| `pnpm typecheck` | `tsgo --noEmit` in every package                                            |
| `pnpm test`      | `vitest run --typecheck` in every package                                   |
| `pnpm cli <args>`| Run the CLI from source with `tsx` (no build needed)                        |

### Package exports (tsdown auto exports)

Never hand-edit `exports` / `publishConfig` / `bin` in a package.json — they are generated by `tsdown` (`exports: { devExports: true }`). Add a subpath by adding an entry to `tsdown.config.ts` and running `pnpm build`. `devExports` points `exports` at `src/**/*.ts`, so in-repo consumers (tsx, tsgo, vitest) never need a prior build.


## After Implementation

**MUST run before completing any implementation task:**

```bash
pnpm lint && pnpm typecheck
```

- `pnpm lint`: Ensures code style and catches potential issues
- `pnpm typecheck`: Uses `tsgo` (TypeScript native compiler) for fast type checking

Do NOT use `npx tsc` or `pnpm tsc` directly. Always use `pnpm typecheck`.

## Async Code

Return `ResultAsync` (neverthrow) from fallible functions and fold it at the edge with `.match` (see `chaining-neverthrow-results` skill). Do not mix `.then()` / `.catch()` chains with Results.

## Tech Stack

- **Language / runtime**: TypeScript (strict, `isolatedDeclarations` in libraries), Node 24 for the CLI, Cloudflare Workers for the MCP server
- **Build**: tsdown (auto exports); dev runner: tsx
- **Typecheck**: tsgo (`@typescript/native-preview`)
- **Lint / format**: oxlint / oxfmt
- **Test**: vitest
- **Errors / async**: neverthrow + error classes; validation: zod; dates: dayjs (utc + timezone)
- **MCP server (later)**: Hono with `Variables.services` DI (see `shared.md`), `@modelcontextprotocol/server`, Cloudflare Access + MCP Server Portal
