# サブタスクを別カードにするタスクボード

## 目的

親タスクが doing でも、その中の一部のサブタスクが未着手であることがボード上で見えない。
サブタスクを 1 枚のカードとして、それぞれ自分の状態の列に並べ、親と子の進み具合のずれを見えるようにする。

## ゴール / 非ゴール

- ゴール
  - 親もサブタスクも 1 枚ずつのカードにする。列は各タスク自身のタグ `[status: …]` と完了状態で決める
  - サブタスクのカードに「↳ 親タイトル」のラベルを付ける
  - サブタスクを持つ親カードに、列ごとの内訳（todo n / doing n / done n）を出す
  - サブタスクのカードを列の間で動かせる（`set_task_status`）
  - 同じ親を持つサブタスクの間で並べ替えられる（`move_task` に `parentId` を付けて呼ぶ）
- 非ゴール
  - ボード上で親を付け替えること、入れ子を外すこと
  - サブタスクの状態から親の状態を自動で決めること（親は親自身のタグで決める）
- アンチゴール
  - サブタスクの並べ替えで入れ子が外れること（`move_task` を `parentId` なしで呼ぶと外れてしまう）

## 制約

- MCP の書き込みは厳格にする方針（`.claude/rules/mcp-write-strict.md`）。ボードは既存のツール（`list_tasks` / `set_task_status` / `move_task`）だけを使い、サーバー側の変更は `show_task_board` の説明文に限る
- 楽観的更新（`board-state`）は、保留中の操作を base に重ねる今の方式を保つ

## 検討した作り方

1. **`buildBoard` で全タスクを平らなカードにする（採用）**：列分けも並べ替えもカード単位で考えることになるので、データの段階で平らにするのが一番素直
2. 入れ子の構造を残し、表示するときだけサブタスクを別の列にも描く：ドラッグ・キーボード操作・楽観的更新が「カード＝トップレベルのタスク」を前提にしているため、二重に管理することになる。不採用

## 決まったこと

- カードの型に親子の情報を持たせる：トップレベル / サブタスク（親 id・親タイトル）/ 親がページにないサブタスク
- 列の中の並び順は、Google Tasks のアウトライン順からその列のカードだけを取り出した順
- 親カードの内訳は、表示しているリストのサブタスクを数える（楽観的更新が反映された状態で数える）
- いまの入れ子のサブタスク一覧と、その開閉ボタン（`toggleSubtasks`）は削除する
- 並べ替え
  - トップレベルのカード：今と同じ（`parentId` なし、トップレベルのカード同士で `previousId` を決める）
  - サブタスクのカード：落とした位置のすぐ上または下が同じ親のサブタスクである場合だけ許可する。`placement` は、同じ親のサブタスクのうち落とした位置より上にある最後のものの後ろ（なければ先頭）。`move_task` には `parentId` を付ける
  - 違う親のカードの間に落とした場合は拒否して、お知らせを出す（`otherList` と同じ扱いの新しい理由）
  - done 列はこれまでどおり並べ替えできない

## 実装する人に任せたこと（私の判断で決めたもの）

- 親がページ内にないサブタスク（いまの `orphan`）は、ラベルを「↳ 親タスク（未表示）」にして、並べ替えは禁止のまま
- Google Tasks のサブタスクは 1 階層なので、ラベルには直近の親だけを出す
- 拒否したときのお知らせの文言、内訳の見た目（CSS）
